# Передача контекста (1C Интеграция)

**Привет, новый чат!** Если ты читаешь этот файл, значит мы перезапустили сессию, чтобы починить баг с путями в песочнице терминала (sandbox configuration error / macOS path on Windows).

## На чём мы остановились (29 Июля 2026):
1. **Цель:** Настроить прямую синхронизацию 1C (ITSheff) <-> LensFlow без FTP.
2. Мы используем мастер настройки в 1С: **"Синхронизация данных через универсальный формат" -> "Подключение к другой программе через Интернет"**.
3. Для этого мы создали фейковый SOAP-эндпоинт на Next.js (`src/app/api/onec/exchange/ws/[...service]/route.ts`), который притворяется второй базой 1С.
4. **Зачем это нужно:** Как только мастер 1С подключится к нашему эндпоинту, он создаст **узел обмена LENSFLOW**. После этого наш основной код (`client.ts`) сможет забирать и отправлять данные напрямую по SOAP.
5. **Последний баг:** 1С упала с ошибкой при чтении WSDL (`Элемент не найден GetVersions`). Мы добавили генерацию XSD схем (`<wsdl:types>`) в код `route.ts`.
6. Пользователь запушил фикс руками и сейчас проверяет подключение в 1С.

## Что делать дальше:
1. Спроси пользователя, прошел ли мастер 1С дальше после добавления `wsdl:types`.
2. Если 1С выдаст новую ошибку (например, `TestConnection` или `GetIBParameters`), тебе нужно будет подправить XML-ответы в `src/app/api/onec/exchange/ws/[...service]/route.ts`.
3. Когда мастер в 1С успешно завершится, **главная цель будет достигнута** — узел `LENSFLOW` будет создан!
4. После этого можно удалять фейковый эндпоинт и переходить к реальному обмену данными через `UploadData`/`DownloadData`.
